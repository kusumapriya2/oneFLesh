- ORM: Prisma with PostgreSQL

- Email: Nodemailer + AWS SES

## API MODULES — BUILD ALL OF THESE

### AUTH MODULE (apps/api/src/modules/auth/)
Routes:
- POST /api/v1/auth/register           — church admin initial registration
- POST /api/v1/auth/login              — email + password → returns partial token if MFA enabled
- POST /api/v1/auth/mfa/verify         — verify TOTP or SMS OTP → return full JWT pair
- POST /api/v1/auth/mfa/setup          — generate TOTP secret and QR code
- POST /api/v1/auth/mfa/enable         — confirm TOTP works and enable MFA
- POST /api/v1/auth/refresh            — rotate refresh token
- POST /api/v1/auth/logout             — invalidate refresh token in Redis
- POST /api/v1/auth/forgot-password    — send reset link via email
- POST /api/v1/auth/reset-password     — validate token and set new password
- GET  /api/v1/auth/sessions           — list active sessions
- DELETE /api/v1/auth/sessions/:id     — revoke specific session

Security requirements:
- bcrypt cost factor 12
- JWT RS256 — generate key pair on startup if not in env
- Access token: 15min TTL
- Refresh token: 7 days, stored in Redis with user_id mapping
- HttpOnly cookie for refresh token
- Max 5 failed logins → lock account 30 min
- All auth events written to AuditLog

## MIDDLEWARE (apps/api/src/middleware/)

Build all these middleware files:

### authenticate.ts
- Extract JWT from Authorization header
- Verify RS256 signature
- Check token not in Redis blacklist
- Attach decoded user to req.user
- Return 401 if invalid

### authorize.ts
- RBAC middleware factory: authorize(UserRole.PASTOR, UserRole.CHURCH_ADMIN)
- Check req.user.role is in allowed roles
- Return 403 if not authorised

### churchGuard.ts
- Ensure pastor can only access profiles/alliances belonging to their church_id
- Attach church context to request

### rateLimiter.ts
- General API: 100 req/min per IP
- Auth endpoints: 10 req/15min per IP
- AI endpoints: 50 req/day per authenticated user (Redis counter)
- Use express-rate-limit with rate-limit-redis store

### errorHandler.ts
- Global error handler
- Zod validation errors → 422 with field-level messages
- Prisma errors → mapped to appropriate HTTP codes
- JWT errors → 401
- All errors logged to Winston
- Never expose stack traces in production

### requestLogger.ts
- Log all requests: method, path, status, duration, user_id
- Winston transport to file + console

### auditLogger.ts
- Write to AuditLog table for: login, logout, profile create/edit/delete, alliance create/dissolve, church approve/reject
- Include userId, action, entityType, entityId, ipAddress, userAgent

## REAL-TIME (Socket.io)

Server (apps/api/src/socket/):
- Authenticate socket connection using JWT
- Join user to room: user:{userId}
- Emit events:
  - notification:new — when new notification created
  - alliance:updated — when alliance stage changes
  - ai:response — stream AI response tokens (use Anthropic streaming)

Client (apps/web/src/hooks/useSocket.ts):
- Connect on auth
- Listen for notification:new → update Zustand notificationStore → show toast
- Listen for alliance:updated → invalidate React Query cache
- Listen for ai:response → stream tokens into chat UI
